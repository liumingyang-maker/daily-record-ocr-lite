# 专属配方知识系统设计

- 日期：2026-07-27
- 状态：已获用户批准，进入实施
- 分支：`feat/personal-knowledge-layer`
- 基线：`43340f8`
- 通用仓库：`liumingyang-maker/daily-record-ocr-lite`
- 私人仓库：`daily-record-ocr-private`（待创建）
- 首个专属版本：`v1.1.0-personal.1`

## 1. 背景

用户提供的 `C:\Users\97020\Downloads\各个单位` 包含多年积累的客户配方
Excel，也混有报告、合同、标签、成分表、报价、PDF、Word、图片和 macOS
元数据。专属版本需要先从结构明确的配方 Excel 创建第一份业务数据库，再让
新上传图片的识别结果持续补充配方历史和业务词库。

当前程序已有 SQLite 知识库框架，但本机活动库中的客户、产品、材料、配方和
配方明细均为零。现有历史匹配仅在 VLM 之后对材料名执行无上下文模糊匹配，
不足以实现用户要求的“低可信文字先结合客户、产品和历史词库纠偏”。

## 2. 已确认目标

1. 从历史 Excel 创建用户第一份专属配方历史和识别辅助词库。
2. 有效配方可按客户、产品、日期、材料、工艺和注意事项查询。
3. 无日期配方仍进入正式历史，显示“未知”，并保留原表位置。
4. 用户确认的新配方立即加入正式历史和识别词库。
5. OCR、VLM 和知识库共同工作，但知识库不得改写数量、日期或编号。
6. 多图任务可以产生多张独立配方卡，用户可编辑、增删和确认。
7. Excel 导出接近历史格式：每客户一工作簿、每产品一工作表、配方块横向展示。
8. 通用仓库提供 AI 标准数据包协议、Schema、提示词和校验工具。
9. 私人仓库保存专属数据库、证据、构建配置、审计和 Windows Release。
10. Windows 安装包内置运行环境、OCR 模型、专属初始数据库和默认视觉配置。

## 3. 非目标

- 本次不支持 macOS、Linux、Windows 7 或 Windows ARM64。
- 不自动解析报告、合同、标签、报价、成分表、PDF、Word 或普通图片中的配方。
- 不上传完整原始 Excel、PDF、Word、图片或 `__MACOSX`。
- 不把 Token Plan 作为生产视觉端点。
- 不训练新的 OCR/VLM 神经网络。
- 不让知识库根据历史配方补写新图片中的数量、日期或编号。
- 不以 Mock 结果替代真实 OCR、真实 Qwen 或真实安装验收。

## 4. 数据边界

### 4.1 自动处理

- 一级客户目录中的结构明确配方 `.xlsx` 和可安全读取的 `.xls`。
- 文件名、工作表名、标题或配方块可明确提供客户和产品。
- 至少包含一组材料与数量且没有失败、废弃、作废标记的配方。

### 4.2 排除

- `__MACOSX`、`._*`、`.DS_Store`。
- 报告、合同、标签、报价、成分表和普通业务表格。
- PDF、Word、图片和压缩包。
- 标记为失败、废弃或作废的配方记录。

排除的失败、废弃、作废配方仍可贡献经过分类的客户、产品、材料、工艺和专业
词组，但不能贡献数量、日期、编号，也不能成为正式配方或配方相似度先验。

### 4.3 不确定数据

- 客户优先来自一级文件夹，产品优先来自工作表名和配方标题。
- 客户或产品冲突、表格结构歧义、疑似别名进入待确认。
- 无法确定客户的“通用配方”不保存配方，只提取合格词条。

## 5. 配方抽取规则

历史工作簿中的典型块为：

1. 产品或标题行；
2. 可选日期；
3. `配方` 行及横向材料名；
4. 下一行的原始数量文本；
5. 可选 `工艺` 行及参数名；
6. 下一行的参数值；
7. 可选注意事项、客户反馈或调色说明。

抽取器必须：

- 保留原始数量文本，不猜测或拆分单位；
- 保留工艺和注意事项原文；
- 对明确工艺参数另建结构化索引；
- 保存来源文件、工作表和单元格范围；
- 生成配方紧裁图和带上下文裁图；
- 使用客户、产品、日期和规范化内容指纹去重；
- 相同内容的重复来源合并，但保存全部 provenance；
- 不同日期始终为不同历史记录。

同一客户、产品下先按业务日期排序。无日期记录根据原工作表中与前后日期块的
相对位置插入；没有可靠锚点时按录入顺序排列。用户补日期后页面顺序可以更新。

## 6. 数据库结构

使用一份普通 SQLite 数据库，依靠 Windows 账户和私人电脑保护，并在批量导入、
升级和迁移前自动备份。

### 6.1 正式业务数据

- `customers`
- `products`
- `formulas`
- `formula_items`
- `formula_process_parameters`
- `formula_notes`
- `formula_sources`
- `formula_evidence`

配方编辑直接覆盖活动业务记录，不向用户创建修订历史。删除使用软删除并可恢复。

### 6.2 识别辅助词库

- `lexicon_terms`
- `lexicon_aliases`
- `lexicon_context_stats`
- `lexicon_cooccurrences`
- `lexicon_feedback`

词条类型限制为客户、产品、材料、工艺和专业注意事项。每个词条保存规范名称、
原始写法、来源、上下文、出现频率、采纳次数、拒绝次数和可信等级。

### 6.3 导入与审核

- `knowledge_imports`
- `import_candidates`
- `import_exclusions`
- `import_sources`
- `import_evidence`

高可信候选直接进入正式历史；冲突、缺字段和歧义项进入待确认。所有排除均有
机器可读原因。

## 7. 受控学习

用户确认一张配方卡时，在同一事务中：

1. 写入或更新正式配方；
2. 将已确认客户、产品、材料和工艺加入词库；
3. 更新客户—产品、产品—材料和材料—材料的上下文统计；
4. 保存 OCR/VLM 原值、最终值和用户反馈；
5. 使下一任务立即看到新知识。

确认过的规范名称立即可用于精确匹配。用户把 OCR 值改成规范值时，错误写法先
成为待观察别名；重复确认或用户明确批准后，才有资格参与自动纠正。

## 8. 识别算法

正式流程为：

`质量检查 → 自适应预处理 → OCR候选 → 配方卡切分 → 前置知识检索 →
单卡VLM → 字段融合 → 配方一致性校验 → 局部复核 → 用户确认 → 学习`

### 8.1 OCR

- 保留高、低可信 OCR token 及坐标；低可信 token 不直接成为最终值。
- 默认运行基础增强图。
- 仅在低覆盖、低可信、阴影、倾斜或反光时运行第二增强变体。
- 局部冲突字段生成紧裁图和上下文裁图后再识别一次。

### 8.2 配方卡切分

利用标题、横线、材料/数量排列、日期和空间关系识别独立配方卡。一张图可包含
多张卡，多图任务也不得跨卡或跨页合并业务字段。

### 8.3 前后双阶段知识检索

VLM 前只提供当前卡片相关的少量客户、产品、材料和工艺候选。VLM 后根据字段
类型、文本相似度、客户/产品上下文、材料共现、历史反馈和候选分差重新排序。

知识库是开放候选，不是封闭词典；新名称不得被强制改成最相似旧名称。

### 8.4 自动纠正 Gate

只允许客户、产品、材料、工艺和经过分类的专业词组自动纠正，且必须：

- 候选唯一；
- 达到经真实样本校准的字段阈值；
- 第一候选显著领先第二候选；
- 客户/产品上下文一致；
- 像素、OCR 或 VLM 至少提供可追溯证据；
- 没有新词冲突。

数量、日期、编号和自由备注禁止由知识库自动修改。OCR/VLM 数值冲突必须人工
确认。所有自动纠正显示原值、候选、依据和恢复入口。

### 8.5 置信度

最终置信度由系统根据 OCR、VLM 一致性、bbox 关联、配方边界、知识匹配分数、
候选分差和反馈统计计算，不直接相信 VLM 自报置信度。

## 9. 用户页面

### 9.1 上传

- 多图预览、排序、旋转和删除；
- 图片质量提示；
- 业务阶段进度，不暴露 Provider、Schema 等开发术语。

### 9.2 配方卡工作台

- 左侧原图和证据裁图，右侧业务字段；
- 默认只展开冲突、空值、低可信和词库纠正；
- 支持新增、修改、删除材料、工艺和注意事项；
- 每卡单独确认，也可一次确认全部无问题卡片；
- 高级 JSON 默认隐藏。

### 9.3 知识库

- 客户 → 产品 → 历史配方；
- 支持日期范围、材料、工艺、注意事项、日期未知和待确认搜索；
- 详情显示来源、单元格和证据；
- 编辑直接覆盖，删除软删除。

### 9.4 词库

- 标准名称、常见写法、类型、上下文、出现/命中次数；
- 批准或拒绝别名；
- 合并重复词；
- 禁止词条参与自动纠正；
- 查看纠正证据。

## 10. Excel 导出

- 支持单客户、单产品和全部客户 ZIP。
- 每个客户一个工作簿。
- `总索引` 工作表列出产品、配方编号、日期、状态和注意事项。
- 每个产品一个工作表。
- 配方块横向展示材料行、数量行、工艺行、参数行、日期和注意事项。
- 日期未知显示“未知”，索引标记“日期待补”。
- 导出只读取正式数据库，不读取 VLM 原始响应。

## 11. AI 标准 ZIP 协议

```text
daily-record-knowledge-package/
├─ manifest.json
├─ formulas.jsonl
├─ lexicon.jsonl
├─ provenance.jsonl
├─ pending_review.jsonl
├─ excluded_files.jsonl
├─ validation_report.json
├─ checksums.sha256
└─ evidence/
```

通用仓库必须提供 JSON Schema、正确/错误示例、AI 可复制提示词、校验命令、
打包工具和导入预检。系统校验 manifest、路径、校验和、Schema、证据、排除标记
和重复记录后才允许导入。

## 12. 通用核心与私人专属层

通用仓库保存：

- 数据库迁移和通用接口；
- Excel/AI 包导入框架；
- 词库检索、融合和页面；
- Excel 导出；
- Windows 通用构建逻辑；
- AI 数据处理协议和 README。

私人仓库 `daily-record-ocr-private` 保存：

- 锁定的通用核心版本；
- 专属数据库和证据数据包；
- 私人构建配置；
- 导入与识别效果审计；
- Windows 安装包和 Release 记录。

完整原始资料不上传。API Key 不进入源码、数据库、Git 历史、测试、日志或审计。

## 13. Windows 安装与升级

- 仅 Windows 10/11 x64。
- 安装包包含 Python、PaddleOCR、PP-OCRv6 medium 模型和专属初始数据库。
- 首次安装复制初始数据库；后续升级不覆盖活动数据库。
- 默认视觉配置为 DashScope 兼容端点、`qwen3.7-plus`、`json_object`、
  `enable_thinking=false`、timeout 300 秒。
- 用户可以在设置页替换内置 Key；升级不覆盖替换值。
- 安装、升级、迁移前备份活动数据。
- 无代码签名证书时允许交付未签名安装包并说明 SmartScreen 提示。
- 卸载默认保留用户数据，只有显式清除才删除。

## 14. 真实验收

### 14.1 数据

- 输出总文件数、自动处理、排除、待确认、有效配方、词条、重复和证据统计。
- 按客户、产品和表格结构抽样，与原 Excel 单元格和截图核对。
- 原始资料未修改。

### 14.2 词库 A/B

使用真实图片和真实证据裁图，对同一批字段比较：

- 原始 OCR；
- OCR + VLM；
- OCR + VLM + 知识库。

Gate：

- 自动知识纠正错误数为 0；
- 数量、日期、编号误改数为 0；
- 辅助准确率高于无知识库基线；
- 人工待确认比例实际下降；
- 每次自动纠正可追溯、可恢复。

样本不足时可对真实裁图做缩小、旋转或低清处理，但不得伪造业务文字。

### 14.3 应用与安装

- 普通测试、Ruff、diff check 全绿；
- 真实 OCR 测试不得全部 skip；
- 真实 Qwen 探针和至少一个完整图片任务通过；
- 生成 structured result、Schema、FinalResult 和 Excel；
- Windows 安装包能安装、启动、查询专属数据库和完成一次识别导出。

### 14.4 GitHub 与安全

- 通用功能 PR CI 全绿；
- 私人仓库保持 private；
- Secret 扫描无真实 Key；
- 无原始无关资料、完整模型响应或本机配置进入 Git；
- Release 包含安装器、校验和、manifest、说明和脱敏审计。

## 15. 审计

审查提示词。报告覆盖数据范围、排除项、Commit/PR/Tag、测试与 CI、真实 OCR、
真实 Qwen、词库 A/B、Secret 扫描、安装验收、Release 资产和遗留风险。
