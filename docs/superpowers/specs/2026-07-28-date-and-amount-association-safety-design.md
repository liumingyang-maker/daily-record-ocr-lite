# 日期恢复与数量关联安全修复设计

日期：2026-07-28
分支：`feat/personal-knowledge-layer`
PR：#9（继续保持 Draft）

## 目标

修复真实两图任务中两个相关的 P0 数据问题：

1. 第一页日期虽然出现在 OCR 行中，但 Qwen 留空后没有受限的本地恢复路径；
2. 第二页横向数量被 OCR 粘连成一个长数字 token 后，同一个 token 被错误复用于全部 amount 字段，
   覆盖了 Qwen 已返回的独立数量。

本次不修改 OCR/VLM 对整图识别的方式，不改变知识库的数字保护策略，不覆盖现有 Job。

## 已确认根因

### 日期

- Qwen 对第二页输出 `24.7.10`、`24.7.19`，说明日期字段和投影本身可工作；
- Qwen 对第一页五条配方的日期全部留空；
- OCR 在每条配方第二行产生了含日期的粘连 token，例如 `22/913（kg）20`；
- 当前日期形态匹配只用于审查证据定位，没有进入 Fusion/FinalResult。

### 数量

- 第二页两条配方的 `record_bbox` 均为空；
- Layout 只生成一个覆盖整页的 record；
- OCR 把第二条数量行合并成一个长数字 token；
- `_from_layout()` 在没有材料 token/bbox 锚点时仍选择全页最高分 pair；
- 每个 amount 独立调用关联器，导致同一个 OCR token 被重复分配；
- Fusion 把高置信 OCR 冲突值作为当前展示值，因而页面所有数量都变成同一个错误值。

## 方案

### 1. 数量候选必须有字段级锚点

Layout amount 候选只有满足以下至少一项时才能进入 Fusion：

- material 名称的证据 token 与 pair 的名称 token 相交；
- material 名称 bbox 与 pair 名称区域有可靠空间关联；
- pair 的名称是可证明唯一的字段级名称匹配，并且存在配方边界约束。

没有字段级锚点、只有整行或整页 pair 时，候选必须拒绝。拒绝 OCR 候选后保留 VLM 原始数量，
由于缺少明确 evidence，字段保持 `NEED_REVIEW`，不自动确认。

### 2. 禁止粘连数量作为单字段值

明显包含多个横向数量的 OCR token 不作为单个 amount 候选。判定只基于结构与边界，
不使用正则拆分后猜测每个字段，也不把粘连长数字擅自拆成业务数量。

同一个 OCR token 若可能服务多个 amount 字段，必须 fail-closed：不允许它覆盖任何字段，
仅保留为页面原始 OCR 证据。

### 3. 受限日期恢复

仅当 VLM `record_date.value` 为空时尝试本地恢复：

1. 使用页面内配方顺序、配方标题锚点和相邻锚点中线确定当前配方区域；
2. 只检查该区域内、位于配方标题后方且靠近第二行的 OCR/Layout 文本；
3. 接受可恢复为合法 `20yy/m/d` 语义的两位年份日期，保留原始短格式文本；
4. 月、日必须组成真实日历日期；不完整、歧义或跨区域候选一律拒绝；
5. 本地恢复值写入 Fusion 候选并标记 `NEED_REVIEW`，来源为 `ocr_base`；
6. VLM 已有日期时绝不覆盖；知识库永远不能修改日期。

允许的真实样式包括 `22/9/3`、`22/9/19`、`22/9/27`、`22/12/12`、`23/1/7`、
`24.7.10` 和 `24.7.19`。OCR 字符粘连只能在配方区域、日期行位置和合法日历约束同时成立时
产生待确认候选；无法唯一恢复时保持空值。

### 4. 旧数据与用户编辑保护

- 不改写已有真实 Job；
- 不覆盖其中已有的人工日期或材料修改；
- 修复完成后使用相同两张源图创建新 Job；
- 新旧 Job、OCR、Vision、Fusion、FinalResult 和审查证据分别保存；
- 新 Job 仍须由用户确认后才能 READY、写知识库或导出正式 Excel。

### 5. 私人知识库绑定

- 私人历史数据库、证据、源工作簿和导入包只存在于本机私人数据层或未来的私人安装数据包；
- 通用 Git 仓库只保存数据库协议、导入器、路径解析和安全测试，不保存任何私人配方值；
- 私人运行版本的页面、识别检索、用户确认、知识写回、纠错日志和导出必须解析到同一个数据根目录，
  禁止只覆盖页面路径而导致读写分叉；
- 数据绑定前自动备份目标数据库；升级时保留已有数据库、设置和密钥；
- Git Secret/私人数据扫描必须覆盖数据库、证据图片、原始响应、源文件和本机绝对路径。

## 数据流

```text
整图 OCR + 整图 Qwen
        ↓
页面/配方结构边界
        ↓
字段级候选关联
  ├─ 有可靠材料锚点：允许 amount OCR 候选
  ├─ 无字段锚点或粘连 token：拒绝覆盖，保留 VLM
  └─ VLM 日期为空：在同配方第二行寻找受限日期候选
        ↓
Fusion（冲突和本地恢复均 NEED_REVIEW）
        ↓
FinalResult → 配方卡片人工确认
```

## 测试与验收

### 自动化回归

1. 无 record bbox、无材料锚点时，粘连长数字不得进入任何 amount；
2. 同一个 OCR token 不得成为多个 amount 的最终值；
3. VLM 已返回的各个独立数量保持原值；
4. VLM 日期为空时，同配方第二行的七种日期样式产生 `NEED_REVIEW` 候选；
5. VLM 已有日期不被 OCR 覆盖；
6. 非法日期、数量、工艺数字和相邻配方日期不被误用；
7. FinalResult、审查页和 Excel 投影继续保留日期原始写法；
8. 全量非真实测试、Ruff、diff check 和 Secret 扫描通过。

### 真实同图 Gate

新 Job 必须满足：

- 第二页不再出现全部数量被同一个粘连长数字覆盖；
- Qwen 已识别数量保持各自独立值；
- 第一页日期若能唯一恢复则显示为待确认候选，不能唯一恢复则保持空值；
- 第二页 `24.7.10`、`24.7.19` 保持不变；
- 生成 structured_result、Fusion、FinalResult 和裁剪证据；
- Job 进入 `REVIEW_REQUIRED`，不伪造用户确认、READY 或 Excel Gate。
